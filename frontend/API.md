# Предлагаемый контракт бэка v1

Это контракт для будущей реализации, а не уже работающий сервер. Базовый путь `/api`. Ответы JSON, `Content-Type: application/json`. Модель `Movie` и связанные типы описаны в `src/lib/types.ts`.

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/collections` | `{ topics: Collection[], moods: Collection[] }` |
| GET | `/recommendations?topic=detective&mood=cozy&primary=mood&refinement=humor&query=...` | `{ movies: Movie[], relaxed: boolean, message?: string }` |
| GET | `/movies/:id` | `Movie` или HTTP 404 |
| GET | `/movies?ids=6553389,proto-knives` | `Movie[]` в порядке запрошенных ID; неизвестные ID пропускаются |

`topic` — ID темы; `mood`, `primary`, `refinement` и `query` необязательны. `primary`: `topic` (по умолчанию) или `mood`. При `primary=mood` тема не ограничивает выдачу: выбранное настроение ведёт подборку по всем темам. Выбор темы снова переключает `primary=topic` и очищает настроение.

`refinement` — последнее действие пересборки, а не список включённых фильтров: `humor`, `energy`, `animation`, `cozy`, `tension`, `thoughtful`, `childhood`; `lighter` поддерживается для старых ссылок. Новое действие заменяет предыдущее. Фронтенд хранит историю использованных кнопок отдельно и не отправляет её серверу. Текст в интерфейсе хранится в URL-параметре `q`; HTTP-клиент отправляет его как `query`.

Выдача содержит до 9 уникальных фильмов в порядке рекомендации. Фронтенд раскрывает их порциями по три без нового запроса; новое пожелание запрашивает новую выдачу. Сервер не должен менять уже полученный список при локальном расширении. `relaxed=true` и `message` поясняют ослабление условий. Для малого набора данных лучше вернуть близкие варианты, сохранив совпадения первыми.

`Collection`: `id`, `title`, `description`, `posters: string[]`. Массивы `topics` и `moods` содержат готовые подписи и постеры для коллажей. ID стабилен, название допускает изменение.

`Movie`: строковый `id`; `title`, `year`; `runtime`, `kp`, `imdb` допускают `null`; массивы `genres`, `countries`, `topics`, `moods`, `people`, `awards`, `media`, `links` могут быть пустыми; `reviews` допускает `null`. `poster` обязателен. `age`, `originalTitle`, `badge` необязательны. Короткие `mood`, `logline` используются в каталоге, `synopsis` — на странице фильма.

`media`: `type` (`image`/`trailer`), `image`, `label`; для трейлера `url` ведёт на источник, `embedUrl` добавляется только для известного разрешённого встраиваемого плеера. `people.photo` необязателен. Награды различают `win` и `nomination`.

`reviews`: `praise: { label, query }[]`, `caveats: string[]`, `sources: { label, url }[]`. Тезисы должны опираться на источники. Фронтенд не синтезирует отзывы из аннотации. `links` — проверенные переходы к площадкам; текущий контракт не утверждает наличие подписки или конкретную цену.

URL изображений и внешних переходов — относительные пути с `/` либо проверенные HTTP(S)-адреса. Добавленные фильмы пока используют пространство ID `proto-*`; при импорте на бэк можно заменить их реальными ID, предусмотрев миграцию сохранённых списков.

HTTP-клиент передаёт `AbortSignal`, отменяет устаревшие запросы, ограничивает ожидание 12 секундами и обрабатывает неуспешные статусы/не-JSON ответы. UI показывает ошибку и кнопку повторного запроса. Пользовательские списки пока остаются локальными; отдельные ручки для них потребуются при добавлении аккаунтов.
